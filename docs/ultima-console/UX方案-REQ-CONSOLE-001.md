# Ultima Console UX 设计方案（修订版 v0.2）· REQ-CONSOLE-001

- 版本：v0.2（IA 重构）｜ 日期：2026-10-18 ｜ 状态：待拍板
- 修订说明（v0.1 → v0.2，按 Owner 意见 + 深度研究重构）：
  1. 左侧导航由 4 组减至 3 项：**总览 / 产品 / 系统**；"仪表盘"改名"总览"
  2. 右侧主内容 = **产品卡片集合**（所有产品平铺可见，四板块分组），默认打开即见
  3. **取消"双通道"导航项** → 通道改为卡片标签（Codex / DeepSeek）
  4. **取消"审计评分"导航项** → 审计并入产品详情钻取，评分并入总览汇总 + 卡片标识
  5. **审批助手改为悬浮球**（有审批时亮起弹窗），不占导航
  6. 内容区宽度自适应，不横向溢出
- 上游：产品策划方案 v0.2（已冻结）/ REQ-CONSOLE-001｜决策依据：决策书 PD-2026-01

## 一、产品理解（本设计的前提）

### 1.1 产品是什么

Ultima Console = **单 Owner 的 AI 产品群监督中枢**。Owner 同时推进多个 AI 开发产品（UltimaRadar / UltimaGold / UltimaM2 / UltimaGame / UltimaEngine / UltimaAgent / UltimaConsole 自身等），进度、工单、审计、文档分布在本地 / GitHub / 飞书。本产品把这一切收敛为"打开平板即见全局"。

### 1.2 核心价值（策划方案 v0.2 提炼）

| 价值 | 含义 |
|---|---|
| 一屏见全局 | 所有产品状态、评分、偏移、阻塞在一处呈现 |
| 3 步到细节 | 从全局到工单/审计不超过 3 步（≥90% 达标） |
| 只出结果 | 界面不显示沟通过程，全部为标准制式结果 |
| 拍板有依据 | 小助手给建议 + 影响分析，Owner 审核后下达指令 |

### 1.3 用户任务模型（Owner 的四个动作）

| 动作 | 频次 | 对应界面 |
|---|---|---|
| 看全局 | 每天 | 总览 + 产品卡片集合 |
| 查细节 | 按需 | 产品详情钻取（规划/阶段/工单/审计/评分） |
| 做决策 | 有审批时 | 审批悬浮球（弹窗） |
| 确认闭环 | 每次决策后 | 审批反馈 + 数据源状态 |

**设计推论**：四个动作对应四种界面形态——"看全局"用总览与卡片流、"查细节"用层级钻取、"做决策"用悬浮弹窗（行动与浏览分离）、"确认闭环"用状态回显。这就是本方案布局的来源：**导航只管"看哪一类"，行动用悬浮球，细节靠钻取，不混装**。

## 二、总体布局逻辑（为什么这样布局 + 优势）

### 2.1 布局结构

```
横屏（双栏）：
┌────────────┬──────────────────────────────┐
│ 左侧导航    │ 右侧内容区（默认=产品卡片集合）   │
│ 总览        │  四板块分组卡片流              │
│ 产品        │  （沟通规划中 / 开发中 /        │
│ 系统        │    已开发结束 / 已上线）        │
│            │                              │
│   （悬浮球：审批，有审批时亮起）              │
└────────────┴──────────────────────────────┘

竖屏（独立）：顶部导航（总览/产品/系统）+ 内容下钻；悬浮球常驻
```

### 2.2 为什么这样布局（每条对应一个真实理由）

| 决策 | 理由（源自产品理解） |
|---|---|
| 左侧只留 3 项 | 监督任务只有三类："看全局""看产品""看系统"；每项导航=一类任务，不空挂（原"产品钻取""双通道""审计评分"都是"看产品"的变体，合并） |
| 右侧默认=产品卡片集合 | Owner 最高频动作是"看都有哪些产品、状态如何"；默认打开即见，省一步 |
| 通道做卡片标签 | 通道只是产品的一个属性（Codex/DeepSeek），不是独立任务；在卡片上标注比单独一页更贴近"识别"动作 |
| 审计评分不设导航项 | 审计/评分都是"产品详情"的一部分，不是全局任务；全局需要的是"汇总+异常提示"（总览），细节在钻取 |
| 审批做悬浮球 | 审批是"有就处理"的待办，不是常驻浏览内容；悬浮球+弹窗让待办随时可见但不占主区 |
| 内容区自适应 | 平板宽度有限（2560×1600 横/竖），卡片流按可用宽度自动换行排布，不横向溢出 |

### 2.3 这套布局的优势

1. **导航即任务**：左侧 3 项对应 3 类任务，用户不思考"点哪"，打开就能用
2. **默认即见全集**：主界面直接是产品卡片集合，省掉"先选板块再列产品"一步
3. **行动与浏览分离**：审批用悬浮球，浏览用内容区，互不干扰、不淹没
4. **属性标在卡片上**：通道/评分/偏移/状态全部随卡片呈现，信息与对象绑定，不靠记忆
5. **深度可下钻**：卡片 → 详情 → 工单 → 审计逐层展开，浅层不拥挤、深层有路径

## 三、功能区规划（内容 / 文案 / 标注 / 图片 / 交互反馈）

### 3.1 左侧导航

| 项 | 内容 | 文案 | 标注 | 图片 | 交互反馈 |
|---|---|---|---|---|---|
| 总览 | 全局汇总页 | "总览" | 待拍板数角标（有审批时显示数字） | 无 | 选中态高亮；角标随状态更新 |
| 产品 | 产品卡片集合（默认主页） | "产品" | 无 | 无 | 选中态高亮 |
| 系统 | 数据源状态/设置 | "系统" | 数据源异常标识（同步失败时） | 无 | 选中态高亮 |

> 导航不承载审批（审批在悬浮球）；不承载通道（通道在卡片标签）。

### 3.2 总览区（点"总览"进入）

| 子区 | 放哪些内容 | 文案示例 | 标注 | 图片 | 交互反馈 |
|---|---|---|---|---|---|
| 全局指标条 | 产品总数 / 开发中数 / 已上线数 / 卡壳数 / 待拍板数 | "7 个产品 · 3 开发中 · 2 已上线 · 1 卡壳 · 2 待拍板" | 卡壳/待拍板数字红色提示标识 | 无（纯文字+数字） | 数字更新有轻提示 |
| 评分汇总 | 各产品评分一览（条形排布）+ 偏移标记 | "UltimaRadar 92（无偏移）" / "UltimaGold 78（偏移 -6）" | 偏移值带方向标识与"需关注"文字 | 无（条形图属 UI 层呈现） | 点击行 → 跳产品详情 |
| 需关注清单 | 预警命中项（评分降 ≥5 / P0 未关 / 阻塞工单 / 超 7 天未冻结） | "UltimaGold 评分下降 6 分" | 每条带预警类型标识 | 无 | 点击 → 跳对应产品评分页 |

**文案规则**：指标行用"数字+单位+状态词"；预警行用"产品名+问题+量化值"；不出现拟人化或工程英文混用（对齐管理语言规范）。

### 3.3 产品区（默认主内容 = 产品卡片集合）

| 项 | 内容 |
|---|---|
| 组织方式 | 按四板块分组展示：沟通规划中 / 开发中 / 已开发结束 / 已上线（板块名=策划方案 F1 原词）；每板块标题行 + 卡片流 |
| 卡片字段 | 产品名 / 状态阶段词 / 通道标签 / 评分 / 偏移标识 / 阻塞或卡壳标识 / 待拍板数 |
| 卡片文案 | 产品名用正式名（UltimaRadar 等）；状态用标准词（"开发中"）；通道标签用"Codex""DeepSeek" |
| 标注 | ① 通道标签：卡片右上角小标签（Codex=审查通道 / DeepSeek=无审查通道）；② 偏移：评分旁"偏移 +N / -N"；③ 阻塞：卡片带"阻塞"文字标识；④ 待拍板：卡片角标数字 |
| 图片 | **不需要产品图片**——内部监督工具，产品为代码/文档项目，无实图资产；卡片用文字+标识表达，避免装饰性内容干扰"读状态" |
| 交互反馈 | 卡片按压即时反馈；点击 → 产品详情（转场进入）；数据更新时卡片状态刷新有轻提示 |

**为什么卡片不带图片**：产品卡片的信息目的是"一眼读出状态"，不是"展示产品形象"；文字+标识是信息密度最高的形式，图片反而增加读距。

### 3.4 产品详情钻取（点卡片进入）

| 层级 | 页面 | 放哪些内容 | 文案要点 | 标注 | 交互反馈 |
|---|---|---|---|---|---|
| L1 | 产品总览 | 产品介绍 / 规划摘要 / 阶段状态 / 评分与偏移 / 阻塞项 / 小助手摘要 | 介绍用策划方案一句话定位 | 偏移/阻塞标识 | 返回=卡片集合 |
| L2 | 阶段计划 | 阶段性计划与推进状态 | 阶段词标准（规划/开发/测试/发布） | 完成度进度条 | 就地展开 |
| L3 | 工单列表 | 任务计划与工单（状态/阶段/版本） | 工单名 + 状态词（执行中/待审核/已冻结） | 阻塞/超期标识 | 点工单展开 |
| L4 | 工单详情 | 任务单元逐层展开、执行版本/阶段、任务状态 | 单元名 + 版本号 + 状态 | 缺口严重级标识（P0/P1/P2） | 就地展开子层 |
| L5 | 审计报告 | 工单审计：执行情况 / 问题 / 解决方案 / 项目进度 | 结论先行 + 问题清单逐条 | 问题状态（已解决/遗留） | 长内容分块呈现 |
| L6 | 评分与偏移 | 评分构成 / 偏移判定 / 纠正建议 / 问题清单 | 评分=100 基础分按缺口扣分（口径=REQ） | 偏移方向 + 建议项 | 建议项可跳审批 |

**钻取导航**：面包屑（产品名 → 层级名）+ 返回路径始终存在；横屏左栏保留产品信息摘要，竖屏顶部面包屑。

### 3.5 系统区

| 子区 | 内容 | 文案 | 标注 | 交互反馈 |
|---|---|---|---|---|
| 数据源状态 | 本地（权威源）/ GitHub（桥接）同步时间、最近有效状态、离线回退状态 | "本地已同步 10:05" / "GitHub 同步中" / "离线 · 显示 10:05 数据" | 数据时间戳（区分实时/历史） | 手动同步按钮 + 同步进度 |
| 设置 | 通道标签显示开关、刷新频率、关于 | 简短设置项 | — | 变更即保存 |

### 3.6 审批悬浮球（行动项，不占导航）

| 项 | 定义 |
|---|---|
| 形态 | 常驻悬浮球（右下角）；无审批时低显示度，有审批时亮起 + 数字角标 |
| 触发 | 点击 → 审批弹窗（从侧边滑入），展示待审方案：方案来源 / 小助手总结 / 建议与影响分析 / 同意 / 打回 |
| 文案 | 弹窗标题"待审批"；操作"同意""打回（需附原因）"；反馈"已反馈文档库" |
| 标注 | 每个待审项带来源产品与类型标识（方案调整/任务变更） |
| 交互反馈 | 新审批到达时悬浮球亮起 + 轻提示；弹窗滑入有转场；操作成功有明确反馈 |

**为什么悬浮球**：审批是低频但必须及时响应的待办；悬浮球让待办可见（亮起+角标）但完全不打扰浏览主区。

## 五、用户流程（主流程 / 分支 / 异常四态）

### 5.1 主流程（打开 → 看全集 → 钻取 → 审批 → 闭环）

```
启动 → N02 产品卡片集合（默认，四板块分组，一眼见全部产品状态）
  → 点卡片 → N03 产品总览 → N05 工单列表 → N06 工单详情（任务单元展开）→ N07 审计报告
  → 有方案待审 → 悬浮球亮起 → S1 审批弹窗 → 同意/打回 → 反馈文档库（后台）→ 状态回显
```

### 5.2 分支流程

| 分支 | 触发 | 路径 |
|---|---|---|
| 看全局汇总 | 需要整体状态 | 导航"总览" → N01 → 点预警/评分行 → 对应产品 N08/N03 |
| 预警直达 | 悬浮球/总览有预警 | N01 需关注 → N08 |
| 通道过滤 | 只看某一通道 | N02 卡片流顶部分通道筛选（Codex / DeepSeek / 全部） |
| 待审批处理 | 有审批 | 悬浮球 → S1 弹窗（不离开当前浏览页） |

### 5.3 异常四态

| 态 | 场景 | 表现与文案 | 恢复 |
|---|---|---|---|
| 空态 | 板块无产品 / 无预警 / 无待审 | "当前无数据" + 范围说明 | 返回上一级 |
| 错误 | 数据源读取失败 | 错误信息 + 来源 + 重试 | 重试/离线回退 |
| 加载 | 同步进行中 | 加载状态 + 范围 | 完成自动刷新 |
| 断网 | 离线 | 显示最近一次有效状态 + 数据时间戳（不白屏） | 恢复后自动同步 |

## 六、交互规范（动作四段）

**动作 1 · 点卡片钻取**：点击产品卡 → 进入 N03；命中区 ≥48dp 等效；状态：默认/按下/加载；反馈：转场进入，失败错误提示+重试。
**动作 2 · 工单逐层展开**：点击工单条目就地展开任务单元；状态：默认/展开中/已展开；反馈：子层显示，失败提示。
**动作 3 · 审批（同意/打回）**：悬浮球 → S1 → 同意或打回；打回须二次确认+附原因；状态：默认/确认/提交中/成功；反馈："已反馈文档库"。
**动作 4 · 通道筛选**：N02 顶部筛选 Codex/DeepSeek/全部；过滤视图不删数据；反馈：列表刷新+当前筛选可见。
**动作 5 · 手动同步**：N09 点同步；同步中禁用重复触发；反馈：时间戳更新 / 离线标注。
**动作 6 · 预警跳转**：点击预警项 → N08 对应产品；已读状态记录；反馈：跳转目标页。
**动作 7 · 小助手建议**：N03 摘要/审批弹窗展示建议+影响分析；采纳/忽略经确认后反馈文档库；反馈："已反馈文档库，等待任务调整"。

**状态矩阵**：元素（产品卡/工单条目/同意/打回/筛选/同步/预警项/采纳忽略）× 状态（默认/按下/加载/禁用/错误）——同 v0.1 全站统一，此处不再重复展开，实现时按此矩阵执行。

## 七、可用性与无障碍

- **可用性十项**：同 v0.1 全过（系统可见性/心智匹配/返回自由/一致性/防错/识别优于回忆/高频路径短/简洁/错误恢复/就地帮助），其中"灵活高效"由新布局增强：默认即见全集 = 主路径 1 步；钻取 ≤3 步。
- **无障碍六项（WCAG 2.1 AA）**：对比度（正文 ≥4.5:1 / 大文本 ≥3:1 / 界面元素 ≥3:1，UI 层回填数值复核）；非文字标识（状态/预警必有文字伴随）；触控 ≥48dp；焦点可遍历；语义标签；动态内容可控。悬浮球为新增可交互元素，纳入焦点遍历与语义标签清单。
