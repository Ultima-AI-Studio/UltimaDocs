# 14-ADR.md（架构决策记录）

> 格式：编号 / 决策 / 理由 / 后果 / 状态。已决项冻结；OPEN 项待拍板（开工前一次清，见 15 台账）。

## 已决（冻结）

### ADR-001 TTS 锁定 CosyVoice
- **决策**：TTS 用 CosyVoice，本地轻量模型 CPU 可跑；默认中文女声，音色可配置。
- **理由**：用户原话锁定；本地推理无外部依赖，符合四不原则边界。
- **后果**：音质为"可用级"；若需产品级音质，后续走变更评估云端 TTS（不影响架构，TTS 是可选增强）。

### ADR-002 推送重试 5 次指数退避
- **决策**：重试 5 次，退避 2/4/8/16/32s（总等待 62s）；重试不计入首跳延迟口径，只影响成功率。
- **理由**：用户原话锁定；成功率分母按 msg_id 去重，语义一致。
- **后果**：端到端延迟参考指标 <15s，不设门禁。

### ADR-003 链上确认维度拆分
- **决策**：区块确认深度（TRON ≥19 / EVM ≥12，链原生安全参数）与连续确认轮数（≥4，三链一致）并存；订单状态 pending→confirming→confirmed→settled。
- **理由**：v2.34 将两个维度误判为互斥；用户原话"大于三次"字面 = 整数 ≥4。
- **后果**：链安全参数不降级；确认轮数统一可机器判定。

### ADR-004 三链注册表
- **决策**：生效链 = TRON（TRC20-USDT）/ Ethereum（ERC20-USDT）/ BSC（BEP20-USDT），测试网 Shasta/Sepolia/BSC Testnet；主网动作禁止。
- **理由**：统一收款口径与确认口径；新链扩展需沙盒可模拟 + 参数可配置 + 夹具齐全。
- **后果**：链数锁定 3 条，扩展走变更流程。

### ADR-005 依赖白名单
- **决策**：外部依赖仅限 CosyVoice / 推送通道 SDK / 链 SDK / 可视化库 / 测试框架；白名单外禁止；自建沙盒不计外部依赖。
- **理由**：解决"四不原则（不引入新依赖）"与既定依赖的边界。
- **后果**：新增依赖 = A 级变更须拍板。

### ADR-006 商业模式：按时长制会员（CHG-002 修订，2026-10-07 用户拍板）
- **决策**：链上 USDT 按时长购买会员（套餐制，如 30/90/365 天，套餐值见 04 参数基线 member.plans）；邀请奖励只返时长（每成功邀请 +7 天，累加不设上限，无现金/USDT）；**无自动续订**（"自动续订/终身"文案 0 命中合规保持）。
- **理由**：用户拍板"会员时长"概念，原"买断直付"被覆盖（CHG-002）；只返时长规避邀请返佣红线；无自动续订规避商店订阅披露义务。
- **后果**：订单 = 会员套餐购买（orders 增 plan 字段）；users 增 member_expire_at（时长制核心字段）；原"买断直付非订阅"表述作废（v2.35 已加注记）；文案合规仍按 14 词表 + 自动续订/终身 0 命中。

### ADR-010 信号引擎双轨（CHG-001，2026-10-07 用户拍板）
- **决策**：轨道 A = 规则基线（保底，v1.0 即上线）；轨道 B = ML 模型训练/回测并行实验（3060 GPU），样本外回测 + 成本计入验证有效后，冻结模型权重并切换推理组件（A 级变更）。
- **理由**：ML 金融时序预测有效性不可预设；规则基线保证 MVP 闭环不被训练卡死；训练是实验非工单，与验收封闭解耦。
- **后果**：ML 框架（PyTorch GPU）进依赖白名单；训练记 15 台账预研；模型版本写死锁定（04 参数基线 ml.model_version）。

### ADR-011 分布式部署（CHG-001，2026-10-07 用户拍板）
- **决策**：引擎机（3060 GPU 推理）与主服务机分离；信号经消息队列跨机传输（断线重投 ≤5、心跳 30s、降级）。
- **理由**：GPU 推理独立于主服务，避免单机资源竞争；跨机接口契约化（01 §6）。
- **后果**：新增部署拓扑（00 §7）；单点故障靠心跳降级兜底。

### ADR-012 自建推送网关（APS，CHG-001）
- **决策**：APS = 自建推送服务网关（通道适配 fcm/apns/mock/vendor 统一出口），安卓 iOS 共用；不用苹果 APNs 直连作为唯一通道。
- **理由**：与既有"推送服务 + 通道适配"设计一致；安卓先行，APNs 仅是其中一条通道，不阻塞。
- **后果**：推送验收口径不变（成功率按 msg_id 去重、首跳 P95）；通道配置在 09 环境清单第 6 项。

### ADR-013 技术栈冻结（2026-10-07 用户拍板）
- **决策**：后端 Python + FastAPI；数据库 PostgreSQL；移动端原生 Kotlin（安卓 MVP）；CI GitHub Actions；ML 引擎机 Python + PyTorch（GPU）。
- **理由**：FastAPI 与 ML 训练/推理同语言（轨道 B 顺畅）；PostgreSQL 支撑订单幂等与财务对账 diff=0 的并发写入；Kotlin 原生对 FCM 集成最直接；GitHub Actions 自带 macOS runner 为 iOS v1.1 预留。
- **后果**：技术栈变更 = A 级变更；iOS 端技术栈在 v1.1 立项时单独评估（Kotlin → Swift 或跨端）。

### ADR-014 范围与业务规则统一（UGP-04，2026-10-16 冻结）
- **决策**：以 UGP-04 产出的 ScopeManifest / RuleBaseline / FindingOwners 为范围、规则与审计问题的唯一对照事实源；正式目标为 FastAPI/PostgreSQL（ADR-013），当前 SQLite/HTTP 原型只承担过渡和回滚；定价唯一事实源 = subscription_plans 表；邀请 +7 天/滚动 24h ≤5 次/累计无上限（CHG-002）；三链确认门槛不降级（ADR-003）；v1.0 PC 仅 MT5（CHG-003）；PC 登录用 APP 安全码（OPEN-25）；SOL/主网上线与 iOS 首发冲突登记为 DECISION_REQUIRED，未决项不默认为通过、只阻断相关功能。
- **理由**：消除规范/实现/台账不一致（UG-23）与范围漂移；让后续执行器有可机器验证的权威快照。
- **后果**：新增范围/规则/映射变更须同步三份快照及对应 fixture，并经 08 变更流程；未决项（R-05 等）在拍板前保持阻断相关功能。
