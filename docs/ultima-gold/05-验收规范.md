> 执行细则：机器判定矩阵与口径以 v2.35 修复版第三章为准，本文件定义 DoD/封闭/审批/报告四件事。

## 1. DoD 分层完成定义（开发到什么程度才算合格）

| 粒度 | 完成定义（全部满足） |
|---|---|
| 任务级 | ①工单"写什么"全部落地 ②验收清单逐项全绿 ③零编译错误零警告 ④未触碰清单外代码 ⑤提交规范 |
| 工单级 | ①全部 T 通过 ②总验收通过 ③关联文档同步 ④冻结基线标记（stageN-frozen tag） |
| 阶段级 | ①该阶段所有工单通过 ②验收 checklist 逐项打勾 ③下阶段前置核验 |
| 项目级 | ①全阶段通过 ②总验收清单通过 ③发布包可交付 ④16-功能范围逐项核对无遗漏 |

## 2. 验收封闭与变更流程

- **验收封闭原则**：验收清单即边界；验收时不得追加新需求；清单外发现 = 登记 15 台账 → 新工单 → 后续阶段，不就地膨胀。
- **五层封闭**：任务级（三段式）→ 工单级（范围冻结）→ 阶段级（DoD+冻结门）→ 项目级（功能范围事实源）→ 验收封闭。详见 08-流程清单.md §2。
- AI 自证：每条 Gate 贴命令/日志/diff 输出证据，**禁止"预计通过"**；同一动作失败两次换实现路径；Bug 3 轮收口、5 轮硬上限。

## 3. 审批矩阵

| 事项 | 自动化 | 用户 |

## 4. 阶段报告模板（7 节，每阶段产出，归档 docs/reports/）

1. 阶段概览（结论：通过/有条件/未通过）
2. 任务完成情况（T0–Tn ✅/❌ + 证据）
3. 问题清单（问题/影响/处置/状态；遗留登记 OPEN）
4. 越界与变更声明（清单外改动逐条列；无 = 写"范围内未见"）
5. 验收证据汇总（构建/单测/压测/联调，贴真实输出）
6. 下一阶段前置核验
7. 冻结建议（tag + 是否冻结）

## 5. 机器判定矩阵（引用 v2.35，13 项口径）

| 验收项 | 口径（v2.35 修复版） |
|---|---|
| 信号可复现 | 同一录制夹具两次运行，diff 信号序列 = 0（固定输入前提） |
| 推送成功率 | ≥99.5%，分母按 msg_id 去重，重试不重复计数 |
| 推送延迟 | 首跳 P95 <3s（受理→回执），重试不计入，采样 ≥1000 |
| 订单幂等 | 同 tx_hash 落单数 = 1 |
| 限流 | 拒绝数 == 配置阈值 × 超限请求数（精确） |
| 财务一致 | sum(orders.amount) 按链分组 vs 汇总，diff=0（6 位小数） |
| 防刷 | 24h 邀请发放 ≤5 |
| 文案合规 | 14 词 grep 0 命中 + 自动续订/终身 0 命中 |
| 英文占比 | 非英文行数/总行数 ≤5% |
| 构建产物 | APK >20MB；.ipa >20MB（CI macOS runner）+ sha256 |
| 隐私页 | HTTP 200（沙盒自签） |
| 迁移 | 退出码 0（幂等可重跑） |
| 唯一约束 | 重复插入 → IntegrityError |

## 6. 工程化底线（P0，纳入各工单 DoD）

- 代码审查：独立审查视角（从规范反推改动清单，不沿用作者自述）；缺陷打回修复后重验。
- CI/CD 双轨：`scripts/precheck`（构建+单测+扫描）+ CI 配置；CI 失败禁止进发布。
- 分支策略：main 受保护（禁止直 push）；release/* 发布分支；tag 只打冻结基线（stageN-frozen / vX.Y.Z）。
- 安全扫描：SAST 每次提交/CI 必跑（高危=阻塞合并）；依赖版本锁定 + CVE + License 审查；发布前 SBOM 归档。

## 7. 报告口径（铁律）

时间分列；未见写"范围内未见"；验收按真实口径（不估算不推断）；旧责任列待处理；决策仅列未裁决项。
