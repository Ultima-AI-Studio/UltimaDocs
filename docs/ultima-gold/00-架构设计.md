# 00-架构设计.md（XAUUSD）

> 依据：v2.35 修复版（决策冻结 + G1–G6 门禁）。本文件描述目标架构；模块边界以工单为准。

## 1. 设计目标

- 单机可部署的黄金（XAUUSD）交易信号推送工具：行情 → 信号 → 推送 →（可选）链上收款 → 订单/财务闭环。
- AI 自主连续开发（dev-conductor 工单化），每模块可独立验收、可冻结。
- 面向境外用户，买断制 + 链上 USDT 直付；无商店内订阅、无收益承诺。

## 2. 分层架构

```
┌─ 表现层 ─────────────────────────────┐
│ Android App / iOS App / Web 用户端 / Web 后台（18 模块）│
└──────────────┬──────────────────────┘
┌─ 核心层 ─────┴──────────────────────┐
│ 信号引擎（串行判定）│ 推送服务（重试5次退避）│ TTS（CosyVoice）│
│ 链上确认（区块深度+≥4轮）│ 订单/财务（幂等+对账）│ 防刷/限流 │
└──────────────┬──────────────────────┘
┌─ 接入层 ─────┴──────────────────────┐
│ 行情源（录制夹具 + 实时源适配）│ 推送通道（FCM/APNs/Mock）│ 链 RPC（TRON/ETH/BSC 测试网）│
└──────────────┬──────────────────────┘
┌─ 数据层 ─────┴──────────────────────┐
│ 数据库（orders/users/signals/push_tasks/invites/audit_logs）│ 配置（参数基线）│ 日志 │
└─────────────────────────────────────┘
```

## 3. 模块清单

| 模块 | 职责 | 边界（不做） |
|---|---|---|
| 行情采集 | 回放夹具 `fixtures/recorded_ticks/`；实时源适配层（数据授权待核验 OPEN-01） | 不做策略外的数据加工 |
| 信号引擎 | 规则基线（保底，CHG-001）+ ML 推理组件（可插拔，GPU 推理）；串行判定；固定模型权重 + 固定输入推理可复现 | 训练为并行预研轨道（15 台账），不在工单内；不承诺收益；不触碰链/推送 |
| 推送服务 | 消息投递、重试 5 次退避 2/4/8/16/32s、送达回执计数 | 不做消息内容生成（TTS 另模块） |
| TTS | CosyVoice 本地推理，文本 → 语音 | 不改变信号内容 |
| 链上确认 | 三链区块深度（TRON≥19/EVM≥12）+ 连续确认 ≥4 轮 | 主网动作不执行（Mock+测试网） |
| 订单/财务 | 幂等落单（tx_hash 唯一）、财务对账 diff=0 | 人工补单已删除 |
| 防刷/限流 | 邀请 24h ≤5、限流阈值可配置 | 不做风控推断 |
| Web 后台 | 用户端 6 页 + 后台 18 模块 | 删除类仅管理员人工，无 AI 工具 |
| 数据层 | 表结构见 02-数据模型.md | 不新建表（四不原则） |

## 4. 运行时模型

- **信号判定串行**：行情 tick 驱动，信号引擎单线程串行，判定结果写库。
- **异步任务**：推送投递/重试、链上确认轮询、TTS 合成走异步任务池；异步任务只读行情/订单输入，不并发写信号结果（写库统一走信号引擎）。
- **唯一写入口**：订单状态由链上确认模块独占推进（pending→confirming→confirmed→settled）。

## 5. 核心数据流

```
行情夹具/实时源 → 信号引擎 → signals 表 → 推送服务 → 通道（FCM/APNs/Mock）→ 回执 → push_tasks
订单：支付(测试网) → tx_hash → 链上确认（深度+≥4轮）→ orders(confirmed) → 财务对账 diff=0
邀请：邀请码 → 24h 计数 ≤5 → invites 表
```

## 6. 演进路线

- v1.0：L0 底座 + L1 核心承诺（行情→信号→推送闭环）+ L2 链上/订单/Web 基础（见 16-功能范围.md）
- v1.1：L3 拓展（邀请/公告/工单）
- v2.0：L4 商业化完全体
- **ML 双轨（CHG-001）**：轨道 A = 规则基线保底闭环（v1.0 即上线）；轨道 B = ML 模型训练/回测并行实验（3060），验证有效后切换推理组件（A 级变更）
- 本版本不做清单见 16-功能范围.md；新增能力必须走 08 变更流程

## 7. 部署拓扑（双机 + 自建推送网关，CHG-001）

```
[引擎机 3060]                [主服务机]                    [推送网关（自建 APS）]      [客户端]
行情 → ML/规则信号判定  →MQ→  推送服务/订单/财务/后台/DB →FCM/APNs/厂商→ 安卓 App / iOS App
        （GPU 推理）            （信号经消息队列跨机传输）
```

- **引擎机**：3060 GPU，跑信号判定（规则基线 CPU / ML 推理 GPU）；与主服务机之间走消息队列（断线重传、心跳、降级）
- **主服务机**：推送服务、链上确认、订单/财务、Web 后台、数据库（原单机职责不变）
- **推送网关（自建 APS）**：即"推送服务 + 通道适配"（fcm/apns/mock/vendor），统一出口，安卓 iOS 共用
- **可靠性**：引擎机心跳丢失 → 主服务走降级（文档第七章 8 项降级方案）；信号不丢（消息队列确认机制）
