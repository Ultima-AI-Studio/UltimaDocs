# 设备集群标准（Device Cluster）

- **版本**：v1.0 · 2026-10-16
- **性质**：范式文件（冻结区，变更走评审）
- **来源**：三层架构讨论 + 环境认知/系统体检/智能设备场景

## 1. 硬件设备层定位

智能体服务器背后是以**算力主机为核心的可扩展多设备管理集群**：可接入 NAS、智能传感器、空调、其他 IoT 设备。设备层是服务器的"手"与"感官"。

## 2. 设备层能力（强制五项）

| 能力 | 内容 |
|---|---|
| 设备发现 | 扫描/识别可接入设备（网络、USB、智能家居协议） |
| 设备档案 | 每设备建档案：类型/能力/状态/归属（落 `execution/server` 设备库） |
| 连接与凭证 | 连接方式 + 凭证管理（本地加密，key 不卡死四层同源） |
| 可控性判定 | 可读 / 可写 / 可控制——三者分别判定 |
| 操作执行 | 按可控性执行（读状态/写配置/控制动作） |

## 3. 环境认知（启动即熟悉）

智能体启动后后台自动加载"环境扫描"，落成**持久化环境档案**：

- 硬件：CPU/内存/温度/传感器
- 磁盘：几块盘/容量/已用/空余
- 文件系统：每盘目录与文件
- 应用：安装了什么
- 网络设备：NAS/共享盘/外设
- 智能设备：传感器/空调/IoT（检测、可控性、读数）

> 数据层可直接复用开源监控（Glances / LibreHardwareMonitor），不自研采集（见 references）。

## 4. 诚实边界（强制）

- **检测不到 / 操作不了，必须如实说**，绝不假装已存入/已执行。
- 执行前置检查：设备可发现 → 档案存在 → 凭证有效 → 可控性允许；任一不满足即如实报告并给替代方案。

## 5. 系统体检（诊断→报告→修复）

1. 诊断：读环境档案 + 判定规则（注册表冗余/无用进程/病毒/缺常用工具）。
2. 报告：走汇报范式（"体检了 6 项，发现 2 个问题"——结论先行 + 聚合）。
3. 修复：**先报告，你点头才动**（受控授权）；体检不自动变清理权限。
4. 边界：不冒充杀毒引擎，结果如实标注来源。

## 6. 典型场景闭环

- 存 NAS：接单→检索→征询（"找到了，需要现在播放吗？"）→你说存 NAS→执行存储→回执"已存到 NAS 影视文件夹"。
- 开空调："有点热"→室温（传感器）+ 舒适偏好（L9 记忆）→ 决策目标温度 → 执行 → 透明汇报（"室温 28°C，按你习惯设到 24°C"）→ 征询。
