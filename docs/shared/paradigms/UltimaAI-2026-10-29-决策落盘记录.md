## 决策二：任务工作流范式 G-TASKFLOW-001（全系统一，执行端无关）

**Owner 指令（原话）**：「把 Manager 的工作原理、工作逻辑登记成 Ultima Agent 以后所有任务的处理和工作的逻辑。不管是以后替换了 Codex API 的入口，还是以后用 Deepseek API 接口，都是用这套工作流任务下发的工作流。」

**核心逻辑**：

1. **工作流固定，执行端可变**：任务统一走「登记 → 计划评审 → 执行 → 独立审计 → 有界修复 → 验收 → 冻结」；Codex API / ChatGPT 网页通道 / DeepSeek API / 未来模型均只是**可替换执行适配器**，替换入口不改变工作流本体；
2. **机制固化**：计划评审分离门、独立审计 + 有界修复（≤2）、批准门一次性决策、容量上限（全项目执行中 ≤2 / 每项目 ≤1 / 审计 ≤1）、越界保护 fail-closed（任一差异路径无授权覆盖即拒绝）、回执必报、缺 tag=闭环未完成；
3. **实战依据**：UltimaManager 工作流（plan → plan review → develop → audit → bounded repair → approval → frozen）全量 239+120 复绿验证。
