## 三、硬约束摘要（由各范式定义）

1. **根目录**：所有开发在 `H:\UltimaAI\` 下，产品目录 Ultima 开头，不另起路径。
2. **命名**：产品名 Ultima 开头；Tuppo 字样不再作为产品名。
3. **三端落盘**：GitHub 正式仓（代码）→ GitHub 公开 Gist（product.json 免 token 主源）→ Gitee 镜像仓（`<product>-sync` 备份端），同一制式；授权三查/上传动作/登记表见 ULTIMA-STANDARD §5。
4. **目录结构**：每产品 `docs/tasks/reports/ops/src/artifacts/sync` 统一骨架。
5. **Codex 调用**：显式 `-m` 指定模型（默认 gpt-6.1-sol 已失效，ChatGPT 账号登录版用 `gpt-5.6-sol`）；派发用 `- < dispatch-*.txt` 喂文件；**执行环境（2026-10-28 固化）：Codex CLI ≥0.165.0，派发必须设精简 `CODEX_HOME=C:\Users\Administrator\.codex-cli`（无插件/MCP/notify），全程静默无终端窗口**；只归档+同步≠派发，必须真正触发 `codex exec`；每项目执行中 ≤1、全局执行进程 ≤3；独立审计中 ≤1；工单三段式 + DoR 五项 + 回执必报字段（详见 Codex 外部执行端调用范式）。
6. **任务路由**：项目产出型任务由各项目方自主转工单、自主派发 Codex 执行、豆包只验收交付；交互型任务（问答/决策确认）豆包直做。派发必须遵守规范队列底线（工单三段式 + DoR 五项 + 全局主表登记 + WIP 上限 + 冻结门 + 打 tag 铁律 + 回执必报），禁止绕过规范裸跑。
7. **自主推进 G-DISPATCH-001（2026-10-28 用户拍板，取代 2026-10-24 Manager 唯一调配版）**：各项目自主推进开发，由项目方直接调用 Codex，不再要求经 UltimaManager 统一准入。Manager 保留为可选监督/审计工具，不阻塞产品推进；未建队列的项目先补建 `tasks\queue\` 并登记全局主表再派发，不设绕行通道。
8. **品牌资产**：所有产品品牌引用统一从 `_shared\brand\` 取用（主标/图标/启动页/参考图），禁止各项目散存新版本；变更须登记清单并同步镜像（详见品牌资产库 README）。
9. **UI 样式**：全系产品界面字体（中/英/数字/等宽四类）、字号阶梯（72→24 唯一字号表）、深色色板（禁止自造色）、胶囊标签（圆角 4px/字重 500/角标 10px）、表单与表格样式统一按 `Ultima-UI样式范式.md` 执行，禁止自定义新字号/新颜色/改胶囊形态；**应用图标**统一深底 #0F1420 + **宇航员半身像（astronaut.png）112%、圆角=边长×22%、边框裁切躯干**、桌面/Web 同 112% 比例、禁止图标内文字（详见 UI 样式范式 §十三）。
10. **项目引导索引**：每产品 `docs\INDEX.md` 必建（模板 `_shared\templates\项目引导索引模板.md`），Codex 派单首段强制引用，缺失 = DoR 不满足、治理体检违规（详见全局根目录范式 §5.2）。
11. **打 tag 铁律（2026-10-28 用户明确要求，全产品默认自动执行）**：**每个关键修改或更新必须打 git tag**（版本冻结 `vX.Y.Z` / 阶段冻结 `mN-frozen` / 工单闭环 tag），tag 与 commit 一一对应、可解析可回滚；完成即自动打 tag 并推送，**无需逐次询问确认**；"声称完成/冻结但无 tag"= 闭环未完成、冻结门未闭合。防进度偏差导致开发倒退（详见 Codex 外部执行端调用范式 §6.1）。
