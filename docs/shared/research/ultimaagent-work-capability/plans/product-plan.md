# 产品方案（Product Plan · v2.3 冻结版）

- **版本**：v2.3 · 2026-10-16（由产品经理 Skill 基于《图波智能体·后端范式共识》、三层架构范式、能力清单、平台战略、调研与 ADR 产出；v2.3 匹配度审计 P1 补全）
- **性质**：规划文件（`docs/plans/`，产品决策人维护；与 capability-list / platform-strategy / roadmap / tech-decisions 互为镜像）
- **状态**：✅ **已冻结**（Owner 2026-10-16 全项拍板确认，见 §9）

## 1. 决策问题

在 2026-10 至阶段一交付窗口内，为 **Ultima Agent** 定稿首版产品方案：**目标用户与情境、价值机制、必备能力、本期范围（MVP）、验收口径与不做项**，供后续研发工单与验收执行。本方案不承诺排期与人力。

## 2. 目标用户与情境

| 维度 | 定义 |
|---|---|
| 核心用户 | 个人用户：技术效率导向、拥有自有电脑与设备集群（NAS/智能家居） |
| 使用情境 | 坐在电脑前（首站），用自然语言完成"查/做/管"三类任务；跨设备时希望同一智能体无缝可用 |
| 未满足任务 | 传统软件要"打开应用→找功能→点按钮"；用户要的是"说一句话→智能体编排→组合窗口交付"——语言是唯一入口 |

## 3. 价值机制（策略链）

```
目标用户（个人/自有设备）→ 未满足任务（对话即操作，告别鼠标点击）
→ 价值机制（听得懂·能去做·能交付：意图→编排→执行→组合窗口+语音汇报）
→ 选择玩法（范式定骨跨终端：一套能力层服务所有终端形态；主题换皮）
→ 必备能力（L0-L10 能力层，宿主薄壳）
→ 衡量（自然语言闭环成功率、交付完整度、可信度）
```

**为什么现在**：本地模型（CV3 语音/推理）与开源工具链（A2UI/Pipecat/Copilot Skills/pywinauto）已成熟到可组装；Top 阶段积累的范式共识与执行管线可直接复用（M7 引用）。

**约束优先级**：①范式/治理优先（不失控）②本地优先（隐私/离线）③跨平台抽象（不被单一平台锁死）④执行受控（可信）。

**因此不做**（阶段一）：设备集群完整接入、记忆自学习、macOS/Linux、云端多端同步、音色训练定制。

## 4. 产品形态（Build 决策）

| 决策点 | 选择 | 理由 | 替代（否决理由） |
|---|---|---|---|
| 架构 | 三层：终端宿主薄壳 / 智能体服务器（全部智能）/ 设备集群 | 跨终端只换壳；能力集中演进（ADR-001） | 单机一体化（无法跨端/被平台锁死） |
| 交互 | 对话即操作 + 组合窗口（积木组装）+ 汇报三规则 | 语言是唯一入口；UI 是乐高积木（ADR-002/006） | 固定页面 UI（=套壳应用） |
| UI 协议 | A2UI 组件树基底 + 图波主题令牌（ADR-007） | 免自研、schema 校验安全、主题换皮 | 自研 DSL（成本/演进风险） |
| 记忆 | 自研轻量 + 本地向量（ADR-008） | 可控、许可、本地化 | 重量级框架（算力/集成成本） |
| 语音 | Pipecat 本地全链路 + CV3（ADR-009） | 打断/延迟/隐私 | 云端管线（隐私/依赖） |
| 悬浮形态 | Claw 路线（CSS/JS 流体玻璃球）+ emotionId（ADR-010） | 轻量/主题契合/跨平台 | WebGPU shader（性能/复杂） |

## 5. 必备能力与验收口径（L0-L10）

> 完整能力清单见 capability-list.md；此处给"怎么算做对"的验收口径（每层可测）。

| 层 | 能力 | 验收口径（DoD 级） |
|---|---|---|
| L0 | 终端四 IO（薄壳） | 语音/文字进出闭环；渲染器按 schema 校验渲染；无业务智能逻辑在壳内 |
| L1 | 意图理解 | "查一下任务队列"→ 明确 范围=全部任务/默认不打断；用户认可 ≥90% |
| L2 | 领域知识/技能注册 | "查任务状态"→ 列出该域内容清单（进行中/完成/失败/阻塞/队列顺序） |
| L3 | 执行接入 | 任务队列状态读取（真实状态源）；**环境认知：启动即环境快照（硬件/温度/磁盘/文件/应用扫描）为 L3 基础执行能力**；失败降级不出错（key 不卡死四层）；诚实边界 |
| L4 | 编排与组合窗口 | 任意结果→组件树 DSL→组合窗口；无死页面；流式渲染 |
| L5 | 表达与总结 | "20 个任务 1 个失败"——结论先行/聚合/可下钻；19 个合格的不逐条朗读 |
| L6 | 输出呈现 | 窗口 + 语音同时交付；悬浮球状态绑定（倾听/思考/说话） |
| L7 | 交互循环 | "透明度再高点"→ 调整→重呈现→征询→确认→待命；队列调整（插队/改优先级）；**异步交付三拍（告知"稍等，我整理一下"→进行→交付）为交互循环默认形态** |
| L8 | 行为约束 | 越界写入被拦截；凭证本地加密；高危操作先征询（受控授权） |
| L9 | 记忆（偏好最小记忆） | 偏好记忆（"空调 24°C"类/汇报风格偏好）；完整自学习后置 |
| L10 | 范式引擎 | 交互前完整走 7 环；不可跨环；范式检查强制 |

## 6. 本期范围（阶段一 MVP · Windows）

**MVP 定义**：完成一次核心价值闭环并验证最大风险的最小范围——**"查任务状态"场景的端到端自然语言交付**（智能体任务队列：进行中/完成/失败/阻塞 → 聚合汇报 + 组合窗口 + 悬浮球征询）。

| 项 | 内容 | 服务任务 | 验证假设 |
|---|---|---|---|
| 宿主壳 | WinUI 3 + WebView2 + **悬浮球（MVP 必含）** | 语音/文字进出 + 渲染 + 活体感知 | 薄壳可承载渲染不承载智能 |
| L1-L5 最小实现 | 意图→领域（任务域）→执行（队列状态源）→编排→汇报 | 一句话查任务状态 | 语言可替代鼠标完成查类任务 |
| L6 | 组合窗口 + CV3 语音汇报 | 窗口+语音同时交付 | 组合窗口优于固定页面 |
| L7 | 征询闭环（"你觉得怎么样"）+ 队列调整（插队/改优先级） | 对话即操作可循环 | 调整用说话完成 |
| L8 | 凭证中心 + 受控执行骨架 | 状态只报告、操作（重试/取消）需授权 | 执行受控不越界 |
| 悬浮球 | 图波主题 v1 形态 + 语音状态绑定 | AI 助手可见化身 | 有机液态形态可用 |

> 任务队列状态源：复用 dev-conductor 工单化 + legacy loop 管线经验（M7 显式引用），Ultima 自有任务管线（project-flow 七阶段）为权威状态。

**首期项复查**：每项都能回答"服务哪个任务/验证哪个假设/缺它闭环是否成立"——缺 L7 征询则"调整"断链，缺 L8 则可信度不成立，缺悬浮球则"活体"感知缺失，均保留。

## 7. 不做项（明确禁止进入阶段一）

| 不做 | 理由 | 回补条件 |
|---|---|---|
| 设备集群接入（NAS/传感器/空调） | 阶段二；先验证核心闭环 | L0-L7 闭环验收通过 |
| L9 完整自学习/反思 | 记忆底座 PoC 先行 | 阶段一偏好最小记忆可用 |
| macOS / Linux / 跨端 | 平台战略阶段二/三 | Windows 闭环 + 抽象层就绪 |
| 音色训练定制（"沉稳男声"） | 训练环境已就绪但非 MVP 依赖 | 语音链路 PoC 通过 |
| 云端多端同步 / 账号体系 | 非 MVP；本地优先 | 多端形态出现 |
| **固定业务页面设计**（为每个功能预先画一套定制 UI 页面/固定样式库） | 范式定骨：**只建积木（组件库+主题令牌+schema），页面由 L4 现场用积木组装**——不预先画死任何页面 | 除非范式定骨被否决（永久不做） |

> **澄清**：以上最后一行"不做固定页面" ≠ 不做积木组合。**L4 编排与组合窗口（积木组装）是阶段一 MVP 必做核心**——"查任务状态"就是用组件积木现场组合出一个交付窗口；永久不做的是传统应用那种"音乐页就是音乐页、设置页就是设置页"的预画死页面。组件库、主题令牌、schema 校验（ui-kit-standard / ADR-007）属于"积木"，第一阶段必须建。

## 8. 衡量与反馈

| 信号 | 指标 | 目标 |
|---|---|---|
| 成功信号 | "查任务状态"自然语言闭环成功率（一次对话完成 查→交付→征询） | ≥80% |
| 交付完整度 | 窗口内容覆盖该域内容清单 ≥90% | 任务状态无遗漏 |
| 可信度 | 越界操作拦截率 100%；诚实边界如实率（不假装成功）100% |
| 失败/停止条件 | 阶段一 PoC 超 3 轮迭代仍无法完成 L0-L7 最小闭环 → 停止并复盘（架构/选型重审） |
| 复盘节点 | 每次阶段 DoD 验收后；TD-01/03 PoC 单独复盘 |
