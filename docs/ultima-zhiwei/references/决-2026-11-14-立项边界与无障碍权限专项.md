## 二、无障碍权限专项（V1.0 必做，形态待确认）

### 1. 为什么必做

V1.0 核心主线「页面文本风险识别」要覆盖 APP 内、浏览器、聊天软件三类场景，在**不上传页面原文、不 root、不截屏**的前提下读取屏幕文字，安卓侧唯一可行通道就是**无障碍服务（AccessibilityService）**。替代方案均不成立：

| 替代方案 | 为什么不行 |
|---|---|
| 通知监听（NotificationListener） | 只覆盖通知栏，聊天正文、网页内容读不到 |
| 输入法（IME） | 只能拿到用户自己输入的内容，读不到对方发来的话术 |
| 屏幕 OCR / 截屏 | 需要 MediaProjection 截屏授权，比无障碍更敏感，且持续截屏耗电、低配老年机扛不住 |
| VPN / 抓包 | 只能看流量，看不到渲染后文本，且 HTTPS 全链路不可行 |

结论：无障碍权限不是"加分项"，是**本产品能不能成立的前提**。

### 2. 风险点一：应用商店审核

- **国内主流安卓商店**（华为 / 小米 / OPPO / vivo / 应用宝）对无障碍权限按"敏感权限"管理，通行要求是：① 使用场景与不可替代性说明；② 权限申请前的显著告知；③ 用户可随时关闭；④ 多数商店要求提交功能演示视频或场景说明文档。写法不合规会被驳回或下架。
- **Google Play 极严**：其无障碍 API 政策只允许"帮助残障用户使用设备"的用途，反诈 / 安防类用途通常被判违规。**若未来考虑 Google Play，必须另做合规评估，不能沿用国内口径。**
- **口径红线（重要）**：对外声明必须落在**「适老化辅助阅读」**——帮助视力 / 认知退化的老人看清并听懂屏幕上的文字；**绝不能写成「监控屏幕内容」「读取他人信息」**。同一件事，两种写法一边能过审、一边直接被拒。无障碍服务的 `config` 描述文案、隐私政策专项条款、商店说明文档三处必须口径一致。

### 3. 风险点二：老人信任（比审核更容易失败的地方）

无障碍授权弹窗是系统级高敏感提示（大意是"此应用可查看屏幕内容"），老人看到的第一反应通常是**卸载**。对策建议：

1. **不放进首启流程**：首次启动只做协议 + 基础防护，无障碍授权放到"开启守护"一步，可由家属协助完成；
2. **大字图文 + 语音解释**：用一句口语说清"为什么要看屏幕：为了在骗子发话术时提醒您"，同时明确"只看文字、不截图、不上传"；
3. **白名单生效范围**：只对老人勾选的应用生效（微信 / 短信 / 浏览器等），不是全机常开；
4. **常驻可见状态**：状态栏保留运行提示 + 一键暂停入口，消除"被偷偷监视"的猜测；
5. **可随时关闭**：设置页一键停用，且停用后不反复弹窗骚扰。

### 4. 建议的产品形态（待 Owner 拍板）

**「可选授权 + 无授权降级」**：不授权无障碍时，仍可用剪贴板链接识别、手动粘贴文本检查、AI 语音问答三件事；授权后才获得页面实时识别。这样商店审核慢、老人不授权两种情况都不会让产品变成空壳。

### 5. 上架需备材料（进入技术方案阶段后补齐）

1. 隐私政策「无障碍权限」专项条款（用途 / 范围 / 不采集原文 / 可关闭）
2. 无障碍服务使用场景与不可替代性说明文档
3. 功能演示视频（授权 → 命中风险 → 大字卡片 → 语音播报 → 关闭权限）
4. `AccessibilityService` 配置描述文案（与上述口径逐字对齐）
