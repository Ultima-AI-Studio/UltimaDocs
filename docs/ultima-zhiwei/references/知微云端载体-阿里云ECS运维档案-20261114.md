### SSH 失败的根因（已定位）

1. **直接原因**：`sshd -t` 报 `Missing privilege separation directory: /run/sshd` —— 运行目录缺失（重启后未重建），sshd 校验失败即退出，socket 接到的连接被立即 RST。
2. **历史**：`ssh.service` 于 **2026-10-16 06:23:22 收到 SIGTERM 后停止**，此后未再启动；`ssh.socket` 仍在监听，所以表现为「端口通、握手复位」。
3. **附带限制**：`sshd_config` 中 `PasswordAuthentication no`、`PermitRootLogin yes`，且 `/root/.ssh/authorized_keys` **不存在**，登录只走 `AuthorizedKeysCommand`（阿里云实例连接下发临时 key）。

### 修复需要两步（**未执行，待 Owner 放行**）

```bash
# ① 重建运行目录（重启后仍需重建 → 需 tmpfiles 持久化）
mkdir -p /run/sshd && chmod 0755 /run/sshd
systemctl start ssh.service

# ② 加运维公钥（否则 sshd 起来了也登不上：密码认证已关闭）
#    把主脑 ~/.ssh/id_ed25519.pub 写入 /root/.ssh/authorized_keys（0600）
```

风险提示：加公钥=给本机永久访问入口，属于权限变更，**未经 Owner 同意不擅自执行**。
