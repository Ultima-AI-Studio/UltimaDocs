# 02-数据模型 · UltimaRadar

> 唯一权威源：`backend/db.py`（init_db）。SQLite（WAL + busy_timeout 30s），库文件 `backend/data/ultimaradar.db`。
> 约定：时间字段 `created_at` 为 SQLite datetime('now') 文本；`ts` 为 unix 秒整数；金额单位见 01 接口契约。

## 一、实体总览（19 表）

| 表 | 职责 | 关键字段 |
|---|---|---|
| addresses | 聪明钱地址池 | address(PK)/label/source(own,public)/flags/is_filtered/score/style |
| token_snapshots | 行情快照（每 token 最新一条按 id 取） | address/symbol/price_usd/market_cap/liquidity_usd/volume_h24/change_h24 |
| watchlist | 关注币列表（manual/auto） | address(PK)/symbol/source/added_at |
| signals | 信号流 | level/confidence/reason/smart_buy_count/smart_buy_total_sol/smart_buy_total_usd/smart_buy_avg_price/exit_flag/price_at_signal |
| signal_outcomes | 信号结果回溯（回测） | price_at_signal/price_24h/price_72h/ret_24h/ret_72h/hit_24h |
| smart_money_trades | 聪明钱交易事件 | signature(UNIQUE)/action/passive/mint/token_amount/sol_amount/price_usd/currency/source |
| addr_cursor | 地址事件游标 | address(PK)/last_sig |
| exec_map | 被动地址→执行地址映射 | passive_addr/executor/signature |
| smart_money_executors | 执行地址画像 | address(PK)/observed/is_verified |
| top10_tracking | Top10 上榜追踪 | score/buy_mint/buy_price/ret_24h/ret_7d/bench_ret_7d/settled |
| data_source_keys | 数据源 key（DPAPI 加密） | source(PK)/keys_json/enabled |
| price_cache | 价格常驻缓存 | mint(PK)/price/ts |
| pump_new_coins | pump.fun 新币 | mint(PK)/symbol/smart_buy |
| paper_account | 模拟账户单例 | balance_usd/status(active,paused)/sigma/delay_p75/kelly/sample_n |
| paper_positions | 模拟持仓 | mint/entry_price/qty/status(open,closed)/pnl_usd |
| paper_trades | 模拟成交 | action(buy,sell)/price/slippage/fee_usd/delay_cost |
| logo_cache | 代币 logo 常驻缓存（重启复用，防 Dex 重打） | mint(PK)/logo/ok/ts |
| notify_events | 聪明钱买入事件通知（历史落盘） | mint/symbol/level/amt_usd/ts，UNIQUE(mint,ts) |
| buys_history | 买入榜聚合快照（历史落盘） | window(24h,7d)/bucket_ts/mint/buyers/n/est_usd，UNIQUE(window,mint,bucket_ts) |

## 二、索引

- smart_money_trades(mint) / (address, ts)
- exec_map(executor)；top10_tracking(address, entry_ts)
- price_cache(ts)；pump_new_coins(ts)；paper_positions(mint)；signal_outcomes(signal_id)

## 三、状态字段枚举（详见 11-枚举数值总表）

- addresses.is_filtered：0 正常 / 1 清洗剔除
- signals.level：info/low/medium/high
- watchlist.source：manual / auto
- paper_account.status：active / paused
- paper_positions.status：open / closed

## 四、金额单位口径（2026-10-18 统一审计后）

| 字段 | 单位 | 语义 |
|---|---|---|
| smart_money_trades.sol_amount | 按 currency 区分 | `currency='SOL'`=SOL 数量；`currency='USD'`=USD 当量（稳定币腿）。字段名遗留历史命名，以 currency 为权威 |
| smart_money_trades.price_usd | 按 currency 区分 | USD 腿=USD/token；**SOL 腿为 SOL/token（链上解析倒推，字段名遗留）**——凡做 USD 金额/均价计算处均已按腿换算（trades.smart_events / pumpfun.resonance / api._notify_events） |
| signals.smart_buy_total_sol | SOL | 聪明钱累计买入 SOL 数（两路径统一：fusion=total_sol、pumpfun=分腿折算） |
| signals.smart_buy_total_usd | USD | 聪明钱累计买入美元当量（2026-10-18 新增列；两路径统一为 USD） |
| api buys.est_usd | USD | 买入榜美元当量（usd 腿直用 + sol 腿×SOL价 + 无金额时 DexScreener 现价×累计量估算） |
| top10_tracking.buy_price | USD/token | 上榜时最近一笔买入的币种单价（USD 腿直用；**SOL 腿×SOL现价换算**，2026-10-18 修复，含存量 69 条回填） |
| api top10.net_flow_24h | SOL | 净流入（仅聚合 SOL 腿，USD 腿已过滤） |
| paper 全表 | USD | 模拟账户/持仓/成交统一美元记账 |

> 采集端防脏（gmgn_client）：`sol_amount` 超过 token×px（USD 当量）/SOL价 ×20 倍或 5000 的异常记录直接跳过；
> 存量脏数据（2026-10-17~18 gmgn 百万级 SOL）已清洗（passive=1+sol_amount=0，共 302 条）。

## 五、配置与内存态

- 配置：data_source_keys（软件内填 key，存服务器 DB）；config.py 运行参数（见 04）
- 内存态（非持久，重启可重算/重采）：api.py `_MENTION_CACHE`（热度 15min TTL）、`_WALLET_CACHE`（GMGN 画像 10min）、`_PRICE_CACHE`（引擎价格 5min）；logo 已落 logo_cache 表（见 OPEN-16）
- **本地壳**（双端拆分后）：不持有业务全量表；仅 `backend/data/local_cache.db`（kv 表：接口路径 → 最近成功响应 JSON，24h TTL，VPS 断线兜底）+ `local_config.json`（vps_url/api_token/configured）

## 六、数据保留 / 备份 / 导出（2026-10-18）

- 保留期（config.RETENTION_DAYS，每日 `_retention_loop` 清理，0=不清理）：
  smart_money_trades=7 天（充钱交易 7 天即够，支撑 7d 榜窗口 + 48h 信号融合 + 24h 净流入，长期留档走 /api/export）/
  token_snapshots=14 天（Top10 7 日结算 + 7 天缓冲）/ notify_events=7 天 / buys_history=7 天 / price_cache=7 天；
  signals、signal_outcomes、top10_tracking、地址池、模拟账本不清理（量小且关键）。
  边界设计：清理 `DELETE WHERE ts<since`（严格小于）与聚合 `ts>=since`（大于等于）无缝衔接，7d 榜窗口不缺口。
- 备份：每日 `_backup_loop` 用 sqlite3 backup API 快照至 `data/backups/ultimaradar-YYYYMMDD-HHMM.db`，轮转保留 7 份（config.BACKUP_KEEP）。
- 导出：`GET /api/export?type=trades|signals|snapshots|notify|buys&days=N` 生成 UTF-8-SIG CSV 至 `data/exports/`，轮转保留 20 份（config.EXPORT_KEEP）。
- 新增 3 表（本表一节）：logo_cache / notify_events / buys_history；事件与聚合在生成时同步落盘（UNIQUE 去重）。
