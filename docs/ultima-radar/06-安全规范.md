# 06-安全规范 · UltimaRadar

> 服务类安全契约。原则：外部 Key 只存后端、加密存储、前端零接触；外部内容不可信；执行类操作冻结。

## 一、凭证管理

| 项 | 约定 |
|---|---|
| Key 存储 | `data_source_keys` 表，keys_json 经 DPAPI 加密（Windows 用户级）落库（scripts/save_secrets.py） |
| 前端接触 | 前端永不接触 Key；数据源页只做填/改/启停（POST /api/sources） |
| 明文 | 禁止 Key 落明文文件/日志/README；.env 仅兼容官方 CLI 约定路径（~/.config/gmgn/.env） |
| 轮换 | 软件内改 key 即生效；Helius 多 key 池轮换均摊用量 |

## 二、访问边界

- API 只监听 `127.0.0.1`，不对外网开放；无鉴权（本机单用户桌面应用）。
- 写操作（添加地址/watchlist/改数据源）均做输入校验：
  - 地址：base58 解码 32 字节校验 + 链上验证（verify_onchain），无效拒绝入池
  - watchlist：mint 长度 32–44 校验；symbol 走 DexScreener 解析主标的
- 外部内容（页面/API 响应/新闻）按不可信处理：仅解析为数据，不执行。

## 三、反滥用 / 防刷

- 外部数据源限流熔断（GMGN 全局 3s + 熔断；MadeOnSol 每日配额；RPC 429 退避）
- 懒采集/兜底全部带 TTL 缓存（热度 15min、logo 失败 15min、画像 10min），防止反复打源
- 页面轮询读本地缓存，不触发外部请求（见 04）

## 四、高危操作审批

| 操作 | 状态 |
|---|---|
| 实盘自动跟单（M3） | ❌ 冻结，需安全评审（资金风险） |
| 对外发布/支付 | ❌ 不在本产品范围 |
| 删除用户数据 | 仅用户主动操作（移除关注/地址），后端无自动删除 |

## 五、信任边界

- 前端 index.html 为本地文件，但内容（含未来若加载远程脚本）按不可信执行处理；当前无远程脚本依赖。
- 所有外部 API 数据进入 DB 前不做 SQL 拼接（全部参数化查询），防注入。
